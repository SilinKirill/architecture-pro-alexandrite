# Архитектурное решение по трейсингу

## 1. Анализ системы

Трейсинг необходимо настроить для:

- Shop API
- MES API
- CRM API
- обмена сообщениями между MES API и CRM API через RabbitMQ

Дополнительно в трейсе необходимо фиксировать обращения сервисов к Shop DB, MES DB и 3d files storage.

В трейс необходимо передавать:

- `trace_id`
- `span_id`
- `order_id`
- имя сервиса
- выполняемую операцию
- время начала и длительность операции
- результат выполнения
- HTTP status или информацию об ошибке
- endpoint или очередь, к которым относится операция

---

## 2. Мотивация

Сейчас сложно определить, на каком этапе задержался заказ и какой компонент вызвал проблему.

Сквозной трейсинг позволит:

- видеть путь конкретного заказа между системами
- находить место задержки или ошибки
- контролировать прохождение сообщений через RabbitMQ
- сокращать время расследования инцидентов
- выявлять зависшие заказы до обращения клиента

Ожидаемый эффект:

- сокращение среднего времени поиска причины проблемы
- сокращение времени прохождения заказа между этапами
- уменьшение количества зависших заказов
- уменьшение количества обращений клиентов по задержкам

---

## 3. Предлагаемое решение

Для распределённого трейсинга предлагается использовать OpenTelemetry и Jaeger.

OpenTelemetry-инструментация добавляется в Shop API, MES API и CRM API. Контекст трассировки передаётся между сервисами в HTTP-заголовках, а при работе через RabbitMQ — в заголовках сообщений.

Трейсы отправляются в OpenTelemetry Collector, а затем сохраняются и отображаются в Jaeger. По `order_id` и `trace_id` команда сможет проследить путь заказа и определить, на каком этапе возникла задержка или ошибка.

### Автоматический мониторинг и алертинг

Для автоматического контроля прохождения заказов на основании данных трейсинга формируются метрики длительности и ошибок. Метрики собираются Prometheus. При превышении заданных порогов Prometheus формирует алерт и передаёт его в Alertmanager для отправки уведомления.

## 4. Компромиссы

- Трейсинг позволяет анализировать только те компоненты и операции, для которых настроена OpenTelemetry-инструментация. Если задержка возникает вне отслеживаемых компонентов, её причина в трейсе не будет видна.
- Для сквозного трейса через RabbitMQ необходимо передавать trace context вместе с сообщением. Без этого цепочка между сервисами будет разорвана.
- Сбор и хранение всех трейсов создаёт дополнительную нагрузку и требует места для хранения. При высокой нагрузке часть трейсов можно сохранять выборочно с помощью sampling.

---

## 5. Безопасность

- Jaeger UI доступен только из внутренней сети компании.
- Доступ предоставляется только авторизованным сотрудникам поддержки и разработки.
- В трейсы не записываются пароли, токены, содержимое 3D-файлов и другие чувствительные данные.
- Данные трейсинга передаются по защищённому соединению.
