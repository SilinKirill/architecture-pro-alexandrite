# Выбор и настройка мониторинга в системе

## 1. Анализ системы

Для мониторинга необходимо покрыть основные backend-компоненты исходной C4-диаграммы:

- Shop API
- CRM API
- MES API
- Messages Queue (RabbitMQ)
- Shop DB
- MES DB
- 3d files storage

Особое внимание необходимо уделить:

- MES API — обслуживает операторов, внешний API и выполняет длительные расчёты стоимости
- RabbitMQ — участвует в обмене данными между MES и CRM
- MES DB — обслуживает операции MES, включая получение списка заказов

---

## 2. Мотивация

Яндекс Метрика показывает работу сайта со стороны пользователя, но не даёт полной информации о состоянии backend-сервисов, внешнего API, RabbitMQ и БД.

Мониторинг позволит:

- контролировать нагрузку на сервисы и инфраструктуру
- видеть рост времени ответа и количества ошибок
- контролировать состояние RabbitMQ и БД
- обнаруживать перегруженные компоненты
- выявлять проблемы до появления массовых жалоб клиентов
- принимать решения об оптимизации и масштабировании на основании фактических данных

---

## 3. Выбор подхода к мониторингу

Для API используется RED:

- Rate — количество запросов
- Errors — количество ошибок
- Duration — время ответа

Для инфраструктуры, RabbitMQ и БД используется USE:

- Utilization — использование ресурсов
- Saturation — степень насыщения
- Errors — ошибки

RED позволит контролировать качество работы API, а USE — выявлять нехватку ресурсов, рост очередей и задержки обработки.

## 4. Метрики

| Компонент                    | Метрика               | Зачем                                         | Ярлыки                          |
|------------------------------|-----------------------|-----------------------------------------------|---------------------------------|
| MES API                      | RPS per user          | Контроль нагрузки со стороны внешних клиентов | `user_id`                       |
| MES API                      | Simultaneous sessions | Контроль количества одновременных сессий      | `instance`                      |
| Shop API / CRM API / MES API | RPS                   | Контроль входящей нагрузки                    | `service`, `method`, `endpoint` |
| Shop API / CRM API / MES API | Response time         | Обнаружение замедления API                    | `service`, `method`, `endpoint` |
| Shop API / CRM API / MES API | HTTP 500              | Контроль серверных ошибок                     | `service`, `endpoint`           |
| Shop API / CRM API / MES API | CPU %                 | Контроль загрузки CPU                         | `service`, `instance`           |
| Shop API / CRM API / MES API | Memory utilisation    | Контроль использования памяти                 | `service`, `instance`           |
| RabbitMQ                     | Messages in flight    | Контроль количества сообщений в обработке     | `queue`                         |
| RabbitMQ                     | Dead-letter messages  | Контроль сообщений, обработанных с ошибкой    | `queue`                         |
| Shop DB / MES DB             | Memory utilisation    | Контроль использования памяти                 | `instance`                      |
| Shop DB / MES DB             | Number of connections | Контроль количества подключений к БД          | `instance`                      |
| Shop DB / MES DB             | Database size         | Контроль роста объёма данных                  | —                               |
| 3d files storage             | Storage size          | Контроль роста хранилища                      | —                               |

Дополнительно необходимо собирать бизнес-метрики:

| Метрика                           | Зачем                                            | Ярлыки             |
|-----------------------------------|--------------------------------------------------|--------------------|
| Количество заказов по статусам    | Выявление накопления заказов на отдельных этапах | `status`, `source` |
| Время нахождения заказа в статусе | Выявление этапов, на которых возникают задержки  | `status`, `source` |

---

## 5. План действий

1. Развернуть Prometheus для сбора и хранения метрик.
2. Настроить Grafana для визуализации метрик.
3. Добавить метрики в Shop API, CRM API и MES API.
4. Подключить сбор метрик RabbitMQ и БД.
5. Настроить сбор инфраструктурных метрик.
6. Создать дашборды для API, RabbitMQ, БД и обработки заказов.
7. Настроить алерты на критические показатели.

## 6. Показатели насыщенности

Выбраны показатели, которые отражают рост нагрузки и приближение компонентов к пределу доступных ресурсов.

| Показатель                    | Порог                                              | Действие                                               |
|-------------------------------|----------------------------------------------------|--------------------------------------------------------|
| RabbitMQ messages in flight   | Устойчивый рост в течение 10 минут                 | Алерт, проверка consumers и скорости обработки         |
| DB connections                | Более 80% доступных соединений                     | Алерт, проверка запросов и пула соединений             |
| Simultaneous sessions MES API | Более 80% допустимого количества в течение 5 минут | Алерт, анализ нагрузки и необходимости масштабирования |

Точные пороговые значения необходимо уточнить после накопления статистики о нормальной нагрузке production-системы.
